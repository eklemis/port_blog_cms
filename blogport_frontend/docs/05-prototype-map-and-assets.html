Prototype Map and Asset Manifest

The Figma file had 210 drawn screens and not one connection between them. It now has 376, grouped into six named flows, in both themes. This paper says what is wired, what is deliberately not, and what to pull out of the file when you build.

01

Opening it

Press Shift+Space in the Figma file, or the play button top right. The flow picker lists six entry points; pick one rather than starting from whatever frame happens to be selected.

Read it as a navigation model, not a spec of motion

Every connection is an instant NAVIGATE with no transition. That is deliberate: the transitions that matter in this product are described in the Forms and Interaction Spec with real durations and reduced-motion behaviour, and a Figma smart-animate would only invent a second, competing answer.

What the prototype is for is the question a static frame cannot answer — how do I get from here to there, and how many steps is it?

04

Deliberately unwired

Four things a click would misrepresent, and one that is simply outstanding. Read this before concluding something is missing.

Verification gate → Overview

The gate clears when a verification email is acted on, not when a button is pressed. Wiring a click here would teach the wrong model of a flow whose entire point is that the app cannot move you forward on its own.

Tailor CV → Cover letter

There is no control in the design for this step, so nothing was wired to fake one. Both are reached from the tracker instead. This is a real gap — if the intended journey is tailor-then-write, the tailor screen needs a control it currently lacks.

The state screens

Posts — loading, empty, filtered empty, error and Applications — empty are documentation of one screen's states, not destinations. They are reachable in the file and excluded from the flows on purpose.

Mobile and tablet frames

Drawn but not wired. The navigation model is identical to desktop and the flows above describe it; wiring 140 more frames would restate it rather than test anything new. Worth doing if the prototype is ever used for user testing on a phone.

Four sizing rules, learned the hard way

The tablet set was rebuilt three times. Every defect traced to one of these four, and each is silent — Figma reports nothing, the frame just looks wrong.

A HUG box cannot hold a FILL child

HUG means "size to content"; FILL means "take what the parent gives". Together the box collapses to its widest hug-sized sibling. This is how a 516px Excerpt field became a 44px column — the width of the word "Excerpt". Promote the box to FILL first, or leave the children fixed.

Cap the column, not the row

On a centred layout the outer row is full-bleed and the column inside it carries the gutter. Cap the row instead and the column keeps its old width, leaving a 5px margin where 32 was intended.

Instances resize; buttons and icons do not

A Field should fill its column. A Button should hug its label. Excluding every instance from resizing pins a 480px field inside a 307px card; including every instance squeezes buttons to slivers. The test is whether it currently overflows.

FILL does nothing outside auto layout

A container with layoutMode: NONE ignores layoutSizingHorizontal silently — the call succeeds and changes nothing, so a repair can report success and have done nothing. Manual boxes need an explicit resize, and their height recomputed too, or reflowed text overlaps whatever sits below.

Six checks before a width is called done

Run them over every frame, not a sample. Three separate defects here were reported by a person after an audit had called the same frames clean, and each time the fix was to widen the check rather than patch the frame.

08

Photography

Every avatar and cover in the file is a real photograph rather than a grey box, because grey boxes hide layout problems that photographs expose. None of it ships.

Where it came from

Lorem Picsum for covers and screenshots, Pravatar for faces — both serve Unsplash-licensed photography and both take a seed, which is what makes this reproducible rather than random.

Why light and dark match

Each image is keyed to its node's structural position — the screen name plus its child-index path — so a light frame and its dark twin resolve to the same seed and the same photograph. Keying on the screen name alone would have given the two clones different pictures, because theme clones share a name.

Media tiles are filled only when ready

uploading, processing, failed and archived stay grey. A thumbnail is precisely what those states do not have yet, and filling them would have made four of the six states illegible as states.

What to do at build time

Ship no photograph from this file. Real content comes from the media pipeline; the public profile's own avatar and covers are uploaded by the person whose portfolio it is. If a marketing page ever needs stock, license it deliberately.
